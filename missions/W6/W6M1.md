# Seoul Public Bike ETL Pipeline

이 프로젝트는 서울시 공공자전거(따릉이) 일별 대여 데이터를 수집, 정제, 집계하여 MySQL에 저장하는 멱등성(Idempotent) 기반의 Airflow ETL 파이프라인이다.

## 1. 환경 설정 (Setup)

### 필수 요구사항
- Docker 및 Docker Compose가 설치되어 있어야 한다.
- 서울시 열린데이터광장(tbCycleRentUseDayInfo) API 키가 필요하다.

### 초기 설정 방법
1. 프로젝트 루트에 `.env` 파일을 생성한다.
   ```bash
   cp .env.example .env
   ```
2. `.env` 파일을 열고 다음과 같이 환경변수를 세팅한다.
   ```env
   SEOUL_API_KEY=발급받은_API_키
   MYSQL_ROOT_PASSWORD=원하는_루트_비밀번호
   MYSQL_DATABASE=bike_dw
   MYSQL_USER=airflow_app
   MYSQL_PASSWORD=airflow
   AIRFLOW_UID=50000
   ```
3. Docker Compose를 통해 초기 데이터베이스 및 Airflow 메타데이터를 세팅한다. (최초 1회 실행)
   ```bash
   docker-compose up airflow-init
   ```
   이 과정에서 Airflow 메타데이터 초기화 및 파이프라인 구동에 필요한 파이썬 패키지(`pandas`, `requests`, `tenacity`)가 설치된다.

## 2. 파이프라인 실행 (Execution)

1. 모든 서비스를 백그라운드 모드로 실행한다.
   ```bash
   docker-compose up -d
   ```
2. 브라우저에서 `http://localhost:8080` 으로 접속하여 Airflow 웹 UI에 로그인한다.
   - **ID:** `admin` / **PW:** `admin`
3. `seoul_bike_period_etl` DAG를 찾은 후 **Trigger DAG w/ config** 버튼을 클릭한다.
4. 아래와 같이 2026-06-27부터 2026-06-28까지 데이터를 수집하도록 JSON 파라미터를 입력하고 **Trigger**를 누른다.
   ```json
   {
     "start_date": "2026-06-27",
     "end_date": "2026-06-28"
   }
   ```
5. `Graph` 탭을 통해 진행 상황을 모니터링할 수 있으며, 최종적으로 `load_to_mysql` 태스크까지 초록색으로 완료되면 성공이다.

## 3. 데이터 정제 규칙 (Data Cleaning Rules)

이 파이프라인은 신뢰할 수 있는 데이터 분석을 위해 다음과 같은 정제 규칙을 적용한다.

1. **컬럼 유효성 검증:** API 수집 직후, 필수 컬럼(`RENT_ID`, `RENT_NM`, `USE_CNT`, `MOVE_METER`, `MOVE_TIME`) 누락 여부를 확인한다.
2. **타입 변환 및 결측치 제거:** `USE_CNT`(대여건수), `MOVE_METER`(이동거리), `MOVE_TIME`(이동시간) 컬럼을 모두 숫자형으로 강제 변환한다. 변환 실패(문자열 섞임 등)로 생성된 결측치(NaN) 행은 버린다.
3. **음수 값 필터링:** 비정상 데이터 방지를 위해 수치형 컬럼 중 어느 하나라도 음수(< 0)가 포함된 행은 정상 데이터에서 제외한다.
4. **로깅 처리:** 위 2~3번 규칙에 의해 제외된 **불량 데이터의 총 개수는 Airflow Task Log에 경고(WARNING) 레벨로 기록**되어 추후 데이터 품질 모니터링 시 확인할 수 있도록 하였다.

## 4. 구조 및 멱등성 보장 (Idempotency)

- **클래스 기반 분리:** 데이터 추출(`Extractor`), 검증(`Validator`), 정제/집계(`Transformer`), 적재(`Loader`) 역할을 개별 파일로 쪼개어 객체 지향적으로 구성했다.
- **멱등성(Idempotency):** `station_period_usage` 테이블 적재 시, 동일한 기간(`period_start_date`, `period_end_date`)에 대해 무조건 기존 데이터를 **DELETE 한 후 INSERT** 하는 방식을 채택하여 파이프라인을 여러 번 재실행해도 중복 데이터가 쌓이거나 충돌하지 않는다.

## 5. 실행 결과 (Final Output)

적재 완료 후 MySQL에서 확인한 집계 결과는 다음과 같다.
(터미널 쿼리 예시: 상위 이용량 10곳)

```bash
docker-compose exec mysql env LANG=C.UTF-8 mysql -u root -proot --default-character-set=utf8mb4 bike_dw -t -e "
SELECT station_name, total_usage_count, total_distance_m, total_duration_min 
FROM station_period_usage 
ORDER BY total_usage_count DESC 
LIMIT 10;
"
```
